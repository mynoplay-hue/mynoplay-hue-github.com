# Баг с отчётом импорта ников — что было и почему

## Симптом

На вкладке «Обновить из списка» предпросмотр (Scan) показывал отчёт нормально,
а после нажатия **«Импорт и обновить»** отчёт исчезал: оставалось только
пустое поле ввода. Пользователь не видел, что именно импортировалось.

## Причина

В `index.html` (функция `runImport`) после реального импорта выполнялись строки:

```js
if (!dryRun) {
  importText.value = '';                            // 1) очищаем текстарею
  importText.dispatchEvent(new Event('input'));     // 2) вручную шлём событие input
  refreshAll();
}
```

А обработчик `input` у текстареи делал:

```js
importText.addEventListener('input', () => {
  ...
  importReport.classList.add('hidden');   // 3) прячем только что отрисованный отчёт
  importError.classList.add('hidden');
});
```

То есть отчёт сначала рисовался, а сразу после этого синтетическое событие `input`
скрывало его. Плюс терялся сам текст списка, поэтому нельзя было ни перечитать
отчёт, ни повторить импорт.

## Что исправлено

* Отчёт после импорта **остаётся на экране**, текст списка больше не стирается
  автоматически (его можно очистить кнопкой вручную).
* Отчёт и предпросмотр считаются одним кодом (`DB.planImport`), поэтому
  «Scan» и реальный импорт всегда совпадают по цифрам.
* В отчёт добавлена **самопроверка**: `новые + изменённые + без изменений = всего ID`.
  Если когда-нибудь цифры разойдутся, внизу отчёта появится красная строка.
* Появились недостающие счётчики, которые часто нужны при разборе:
  * «Корректных строк» — сколько строк распознано;
  * «Уникальных ID» — сколько игроков затронуто;
  * «Ников добавлено» — сколько новых ников реально записано в историю;
  * «Повторов строк» — сколько строк повторяли уже встреченный ID+ник;
  * «Строк пропущено» — с номерами строк и текстом.
* Исправлены ещё две ошибки, найденные при проверке:
  * при создании нового игрока в историю не попадали ники (кроме текущего) —
    у новых игроков история была пустой, а «отчёт» расходился со статистикой;
  * при повторном импорте старого списка могли «теряться» удалённые ники —
    теперь они корректно восстанавливаются и попадают в счётчик добавленных.
* Дата/время, сортировка и поиск больше не зависят от формата локальных данных:
  при загрузке база приводится к новой схеме (`normalizeDB`), старые данные
  из localStorage подхватываются автоматически.

## Как проверить

1. Откройте вкладку «Из списка», вставьте 3–4 строки, нажмите «Проверить».
2. Нажмите «Импортировать» — отчёт должен остаться на месте, со статусом «Импорт завершён ✔»
   и строкой «Проверка сходится…».
3. Повторите импорт того же списка — должно быть «Новых 0, сменили ник 0, без изменений N».
